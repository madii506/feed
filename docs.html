01  —  The object

A coin here is a pair: a token and one account.

Launching takes a profile URL from X, YouTube, TikTok, Instagram, Twitch or Kick. The pad resolves it to four things — the platform, the handle, the platform's own account ID, and an avatar — and those are written onto the coin's page at deploy.

The account ID is the binding. A claim is matched against the ID, never the @handle, because handles are sold, renamed and squatted, and a pairing that can be inherited by buying a username is not a pairing.

Note 1Not every platform hands an account ID to a server. Where one does not, the coin page says so on its face and the claim falls back to matching the handle at the moment of the post — which is weaker, and labelled as weaker, rather than quietly treated as the same thing.

02  —  The claim

The wire format, in full.

A claim code is a pure function of the handle. No lookup, no server, no secret — which means anyone can recompute one and check a claim without trusting this site.

fnv1a(s):
  h = 0x811c9dc5
  for each char c in s:
    h = (h XOR codeUnit(c)) * 0x01000193  mod 2^32

code(handle):
  clean = lowercase(strip_leading_@(trim(handle)))
  x     = fnv1a("FEED:" + clean)
  return "FEED-" + last7(pad7(uppercase(base36(x))))

The post itself has no required wording. It has to contain the code, come from the account the coin names, and exist long enough to be read once. Deleting it afterwards does not undo the claim, and posting it in a reply is fine.

What is checked, in order

StepCheck
1  CodeThe posted string contains exactly the code derived from the coin's handle.
2  IdentityThe posting account's ID equals the ID written on the coin at deploy.
3  WalletThe code was issued against a connected wallet, and payment goes to that wallet and no other.
4  HoldA published waiting period runs before the escrow opens. The account can cancel inside it with one more post.
Note 2Step 4 exists because step 2 proves control of an account at a moment, not ownership of it. An account can be taken at 3am and a claim filed at 3:05. The hold is the window in which the real owner says no, and it is the reason this is slower than a competitor that skips it.

03  —  The states

Three words, and every transition between them.

StateWhat it means · how it changes
unclaimedDefault at deploy. The feed's share accrues to escrow and nobody can move it. → claimed by a valid post plus the hold. → returned to holders pro rata at twelve months.
claimedThe share streams to the wallet named in the claim. → unclaimed if the account revokes. → declined if the account refuses outright.
declinedThe escrow returns to holders pro rata and the feed's 60% stops being collected for the life of the coin. → reversible by the account, the same way it declined.

The state is printed as a word at the top of the coin page, in the page's own type size. It is deliberately not a badge or a coloured tick: a badge is a thing you have to already know the code for, and it does not survive being screenshotted.

04  —  The split

Sixty to the feed, forty to FEED.

The creator fee is set by the venue a coin launches on, not by this pad. Whatever arrives splits the same way every time, and both numbers are printed on the coin's page before the first trade.

ItemValue
Feed's share60% of the creator fee
FEED's share40% of the creator fee
Set whenAt deploy, and locked — not governed, not adjustable after buyers arrive
Monthly feeNone
Tiering by follower countNone. The rate on a hundred-follower feed is the rate on a ten-million-follower feed.
Cost to claimNetwork fees only. FEED takes nothing out of the escrow at claim time.
Note 3"Locked" is doing real work in that table. A split that can be changed after people have bought is not a split, it is an intention — and the only way to tell the two apart before launch is whether anyone was willing to write the number down first.

05  —  Declining

What a refusal costs, and who it costs.

When a creator declines, the escrowed share goes back to holders pro rata and the feed's 60% stops being collected. FEED's own 40% is unchanged — it does not grow, and we do not inherit the refused share.

The arithmetic matters more than the promise. If a declined share reverted to us, every refusal would be a payday and the pad would earn most from the creators who want nothing to do with it. Instead the total fee on the coin falls, permanently, and the only party worse off is us.

Note 4A decline does not delete the coin. Nobody can un-issue something already onchain, and a pad that says it can is describing a power no blockchain gives anyone. What it can do is put the refusal at the top of the page in the largest type on it.

06  —  The readers

Every endpoint, with a button that calls it.

These run on this site. Press a button and your browser calls the real endpoint with a real input — the response below is what came back just now, not a sample.

EndpointDoes
/api/feed Resolves a profile URL to platform, handle, account ID, followers and avatar.
/api/avatar Resolves the same input and streams the picture, so no platform CDN is called from your browser and nothing is stored here.
/api/logo Fetches a platform's own mark from its own domain for the strip on the home page.
/api/price The SOL spot price, with its source and the second it was read. The only live figure anywhere on this site.

What a reader returns

GET /api/feed?u=https://twitch.tv/xqc

{ "ok": true,
  "platform": "twitch", "platformLabel": "Twitch",
  "handle": "xqc",
  "name": null,
  "id": "71092938",          // the binding. null if the platform refused it
  "followers": 12345678,     // null where none is published
  "avatar": "https://…",
  "url": "https://twitch.tv/xqc",
  "note": null,              // a sentence when a field could not be read
  "bindable": true }         // false means there is no stable ID to bind to

A field that could not be read comes back null with a sentence in note. Nothing is filled in with a guess, an average or a cached value from an earlier visitor.

07  —  Not verifiable

What this site cannot check today.

  • That the escrow behaves as described. The contract is not deployed. Sections 02 to 05 are a specification, and until an address is published here they are enforced by nothing.
  • That a claim post was not made by someone who stole the account. The hold period is the mitigation, not a proof. A determined attacker with the account and the timing wins.
  • Follower counts, on some platforms. Instagram and TikTok frequently refuse a server read. When that happens the field is null and the note says which platform refused.
  • That a coin's launcher has any relationship with the creator. They almost certainly do not. That is the premise, not a flaw.
  • That an address you saw somewhere else is ours. The token does not exist yet. When it does, the address appears on this site and in the pinned post at the same moment, and anyone posting one before that is scamming you.
  • Anything about trading. Nothing has traded. There is no volume figure, no holder count and no price on this site, because all three would be zero and three zeros under a heading is a dashboard pretending to be a measurement.

08  —  Vocabulary

Six words used precisely on this site.

WordMeans, here
FeedOne account on one platform. Not a person, not a brand — an account with an ID.
ClaimA post from that account containing the coin's code, matched against the ID.
EscrowWhere the feed's share sits before a claim. Not our wallet; not spendable by anyone.
HoldThe published waiting period between a valid claim and the escrow opening.
DeclineA refusal that returns the escrow and stops the share being collected at all.
LockedFixed at deploy and not changeable afterwards by us, by a vote, or by anyone.

09  —  Hostile questions

The ones a sceptic asks first.

"So this is just a pad that lets people launch coins on strangers."

It is a pad that lets people launch coins on strangers and cannot keep the stranger's share. Every other pad in this category has the same first half and no second half. If that distinction is worth nothing to you, the honest answer is that you should not buy one of these.

"The contract isn't deployed, so none of this is real."

Correct, and section 07 says so before you ask. What exists today is a specification published before launch so it can be held against whatever ships, plus readers you can call yourself from section 06. Everything else here is a claim about the future and should be read as one.

"What stops you changing the split later?"

At deploy, the split is written into the coin and not adjustable by us. Before deploy, nothing stops us changing this page — which is why the number is published now, in writing, with a date on the repository rather than only in a pinned post.

"Why should a creator trust a claim code from a memecoin site?"

They should not have to. The code is a pure function of their handle, written out in full in section 02, computable on paper. A creator can derive it themselves, check what they are posting, and verify anyone else's claim the same way.

"Who runs this?"

One person, so far, and no company. If a step in the payout ever requires a human to press send, this page will say which step, who, and what they could get wrong. It does not require one today because there is nothing to send.
